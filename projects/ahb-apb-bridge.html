01OVERVIEW

Bridging Two AMBA Protocols

The AHB-to-APB Bridge enables communication between the AMBA Advanced High-performance Bus (AHB) and the Advanced Peripheral Bus (APB). AHB is intended for higher-performance system communication, while APB provides a simpler interface for low-bandwidth peripherals.

Because the protocols use different transfer mechanisms and timing requirements, the bridge captures the AHB transaction, converts its address/data/control information into APB-compatible signals, performs the APB transfer, and returns read data and completion information toward the AHB side.

Design Objective

Receive AHB Transactions

Identify valid AHB transfers and capture the required transaction information.

Convert the Protocol

Translate AHB address, data and control information into an APB transfer.

Control APB Timing

Generate the required APB SETUP and ACCESS sequencing.

Return Results

Provide APB read data and transaction completion information back toward AHB.

03AHB SLAVE INTERFACE

Receiving the AHB Transaction

The AHB Slave Interface forms the bridge's AHB-side endpoint. It determines whether the incoming transfer is valid and captures the information required by the APB Controller.

Key AHB Signals

HclkHresetnHwrite HreadyinHtrans[1:0] Haddr[31:0]Hwdata[31:0]

Transaction Validity

AHB transfer information is accepted when the transfer is valid, with `Htrans` identifying the appropriate transfer type and `Hreadyin` indicating that the incoming transfer can be accepted. Valid NONSEQ and SEQ transfers are captured and forwarded to the controller.

AHB VALID → capture address + write data + control AHB INVALID / IDLE → no APB transaction initiated

05APB TRANSFER

SETUP → ACCESS

The APB Controller follows the required APB transfer sequence. During SETUP, the address, write data and control information are placed on the bus with the peripheral selected. During ACCESS, `PENABLE` is asserted.

APB Signal Relationship

06WRITE PATH

AHB Write → APB Write

AHB MASTER→ AHB SLAVE→ CAPTURE→ APB SETUP→ APB ACCESS→ PERIPHERAL

For a write transfer, the bridge captures the AHB address and write data, carries the write direction into the APB controller, and drives `PADDR`, `PWDATA`, `PWRITE`, `PSEL` and `PENABLE` appropriately.

07READ PATH

AHB Read → APB Read → AHB Read Data

AHB MASTER→ AHB SLAVE→ APB CONTROLLER→ APB PERIPHERAL
PRDATA→CONTROLLER→HRDATA

For a read, the bridge generates an APB read transaction and receives `PRDATA` from the peripheral. The returned information is routed toward the AHB side as `HRDATA`.

08TOP-LEVEL INTEGRATION

AHB2APB Bridge

The top-level module integrates the AHB Slave Interface and APB Controller. Its primary responsibility is clean signal routing between the two blocks and the external bus interfaces.

AHB Inputs

Clock, reset, transfer type, address, write data and control signals.

Internal Interface

Valid transaction, captured address/data and write-selection information.

APB Outputs

Address, write data, read/write control, peripheral select and enable.

Return Path

APB read data and completion information toward the AHB interface.
