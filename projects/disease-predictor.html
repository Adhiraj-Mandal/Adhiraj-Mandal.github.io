01OVERVIEW

From Symptoms to Prediction

The project implements a machine-learning system that accepts a user's symptoms as text and predicts the most likely disease learned from a disease–symptom dataset. After prediction, the application retrieves corresponding treatment information using a disease-to-treatment mapping.

The implementation demonstrates an end-to-end supervised ML workflow: dataset loading, preprocessing, text feature extraction, label encoding, model training, persistence, inference, and treatment lookup.

End-to-End Pipeline

DATASET→ PREPROCESSING→ VECTORIZATION→ RANDOM FOREST→ SAVED MODEL→ USER SYMPTOMS→ PREDICTION→ TREATMENT LOOKUP
02PROBLEM

Problem Statement

Disease and symptom datasets contain relationships between symptoms and diseases, but the raw information is not directly useful to a user who simply wants to enter a set of symptoms.

The objective was to build a simple ML system that could learn patterns from symptom descriptions and use new symptom input to predict a disease, followed by retrieval of the associated treatment information.

04PREPROCESSING

Preparing Symptom Text

The symptom field is standardized before model training. Missing values in important fields are removed, symptom strings are converted to lowercase, and comma spacing is normalized so that similar inputs are represented consistently.

Label Encoding

Disease names are categorical labels, so `LabelEncoder` converts them into numerical class identifiers for model training. During prediction, the encoded output is converted back into the corresponding disease name.

05FEATURE ENGINEERING

CountVectorizer

Because the input is textual symptom information, it must be transformed into numerical features before classification. `CountVectorizer` converts the symptom text into a numerical representation based on token counts.

Symptom Text → Tokens → Count-Based Feature Vector

Why This Matters

The vectorized representation creates a machine-readable feature space in which the Random Forest model can learn relationships between symptom patterns and disease labels.

06MODEL

Random Forest Classifier

A `RandomForestClassifier` with 200 decision trees is trained on the vectorized symptom features. Each tree produces a classification decision, and the ensemble combines the tree-level predictions to determine the final disease class.

07MODEL PERSISTENCE

Reusable Inference Components

The trained components are persisted using Joblib so the prediction workflow can load the learned artifacts without retraining the model each time.

disease_prediction_model.joblib label_encoder.joblib treatment_map.joblib

Training → Inference Separation

TRAIN→SAVE ARTIFACTS→ LOAD→PREDICT

Separating model training from prediction makes the application simpler to reuse: the trained classifier, label encoder and treatment mapping can be loaded directly for subsequent user queries.

10LIMITATIONS

What the Current Implementation Does Not Claim

The supplied implementation is an educational machine-learning application. It does not calculate or report a dedicated accuracy metric, and it does not implement a Flask web application in the shared project code.

The system should therefore be presented as a symptom-based ML prototype, not as a clinically validated diagnostic system or professional medical decision-making tool.
