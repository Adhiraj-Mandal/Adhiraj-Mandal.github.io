01OVERVIEW

What I Built

The AI-Powered ASIC Design & Verification Suite is a prototype exploring how AI and automation can assist traditional RTL and ASIC-design workflows. Rather than treating RTL generation, optimization, evaluation, and verification as isolated tasks, the project connects them into one software-driven flow.

The prototype combines five major components: an AI-assisted RTL generator, ML-guided design-space exploration and optimization, an ML-based timing and power estimator, low-power AI accelerator hardware IP, and an automated verification framework.

The Design Question

Hardware designers often need to write RTL, modify architectural parameters, simulate candidate configurations, evaluate performance, and repeat the process while exploring trade-offs among power, delay, area, precision, and parallelism.

This project asks:

Can AI + automation shorten the path from hardware specification → optimized RTL → verification?

The generator accepts a high-level configuration such as “MLP with 16-bit data and 4×4 processing array”, extracts the hardware parameters, and constructs parameterized Verilog modules.

Processing Element

Each PE performs local multiply-accumulate computation while forwarding data toward neighboring PEs, enabling the array to execute matrix-style workloads with structured data movement.

04ACCELERATOR IP

Parameterized Systolic Array

The hardware core uses a two-dimensional array of Processing Elements. The architecture is intentionally parameterized so that array size and data width can be changed and explored without manually rewriting the complete RTL structure.

Why Systolic Architecture?

Parallelism

Multiple PEs execute arithmetic operations concurrently.

Data Reuse

Operands move through the array rather than requiring centralized computation.

Regularity

Repeated PE structure maps naturally to parameterized RTL generation.

Scalability

Array dimensions become design parameters for exploration.

Important Scope

The estimator is a prototype model trained on synthetic data. Its outputs should therefore be presented as model estimates, not as silicon measurements or sign-off-quality ASIC timing and power results.

06DESIGN-SPACE EXPLORATION

ML-Guided Optimization

The optimizer evaluates candidate combinations of hardware parameters and ranks them according to the prototype's objective. Example dimensions include bit width and systolic-array size.

4-BIT↔8-BIT↔16-BIT+2×2↔3×3↔4×4

Optimization Objective

LOWER POWER+LOWER DELAY→SELECT CONFIGURATION

The current prototype prioritizes lower power and lower delay. A more rigorous multi-objective formulation can later include area and an explicit AI-accuracy constraint.

Design-Space Visualization

The Streamlit interface presents candidate configurations through a delay-versus-power scatter plot, making architectural trade-offs easier to inspect during exploration.

09ENERGY-EFFICIENCY

Hardware / AI Trade-offs

The project investigates how architectural choices affect the efficiency of AI hardware. Changing numerical precision and array size can influence arithmetic cost, parallelism, power, and delay.

AI ACCURACY↕PRECISION↕HARDWARE COST↕POWER↕PERFORMANCE

Energy-Efficient Direction

Lower precision can reduce arithmetic and storage requirements, while smaller or better-chosen arrays can reduce hardware cost. The key engineering problem is balancing these benefits against accuracy, throughput, and latency requirements.

10RESULTS

Prototype Demonstration

The implemented prototype demonstrates an integrated workflow in which a high-level hardware configuration can be parsed, evaluated across candidate design points, optimized using the ML-based estimates, converted into Verilog, accompanied by a generated testbench, and presented through the Streamlit interface.

What the Current Results Mean

Workflow Integration

Multiple hardware-design automation stages operate through one pipeline.

Parameterized RTL

Hardware structures can be generated from architectural parameters.

Rapid Estimation

Regression models provide fast prototype-level performance estimates.

Automated Artifacts

RTL and verification testbench generation are integrated into the workflow.

What It Does Not Claim

The prototype does not provide production ASIC sign-off, fabricated-silicon measurements, or technology-specific physical-design accuracy. Those require real synthesis, implementation, and power-analysis feedback.
