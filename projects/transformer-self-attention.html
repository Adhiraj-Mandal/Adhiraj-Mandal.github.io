01OVERVIEW

Overview

Transformer self-attention relies heavily on matrix multiplication and dot-product operations. This project explored how those computational kernels can be mapped from an algorithmic representation into a dedicated RTL hardware architecture.

The central design uses a regular 16×16 systolic array containing 256 processing elements. Each processing element performs multiply-accumulate computation while data propagates through neighboring elements, exposing parallelism and local data reuse.

The work therefore sits at the intersection of machine learning, computer architecture, and digital VLSI: translating a modern AI workload into a structured hardware datapath.

Problem & Motivation

Self-attention contains computationally intensive matrix operations, including the formation of query, key, and value projections and the matrix products used in attention. Executing these operations directly on general-purpose processors can involve substantial computation and data movement.

The goal was to investigate a hardware architecture that could exploit the inherent parallelism of these operations through dedicated processing elements and structured dataflow.

02WORKLOAD

03ARCHITECTURE

16×16 Systolic Array

The core architecture is a 16×16 systolic array. The 256 processing elements form a regular grid through which operands propagate and partial results accumulate.

16 × 16 · 256 PROCESSING ELEMENTS
PEPEPEPEPEPEPEPE PEPEPEPEPEPEPEPE PEPEPEPEPEPEPEPE PEPEPEPEPEPEPEPE
Representative PE grid · each cell performs MAC computation

Processing Element

Each processing element performs a multiply-accumulate operation:

ACC′ = ACC + A × B

Partial results are accumulated locally while operands move through the array. This spatial organization supports parallel matrix computation and reduces reliance on a centralized arithmetic unit.

Why a Systolic Architecture?

Parallelism

Many MAC operations can execute concurrently across the PE grid.

Local Dataflow

Operands and partial results move between neighboring processing elements.

Data Reuse

Structured propagation enables reuse of operands during matrix computation.

Regular Hardware

The repeated PE structure provides a regular architecture suited to RTL implementation.

Control Architecture

Datapath and control are separated so that computation and sequencing can be reasoned about independently. The controller coordinates operand loading, computation, propagation, accumulation, output collection, and completion signaling.

IDLE→ LOAD→ COMPUTE→ DRAIN→ OUTPUT→ DONE

Numerical Representation

The design uses hardware-oriented fixed-point/quantized arithmetic concepts to reduce the cost of numerical operations relative to floating-point implementations. Precision, accumulator width, signed arithmetic, and truncation/quantization are architectural considerations that affect both numerical behavior and hardware cost.

06DESIGN TRADE-OFFS

Architectural Considerations

Parallelism vs. Area

More processing elements can increase throughput potential while increasing hardware and routing cost.

Precision vs. Hardware Cost

Wider operands and accumulators improve numerical range but require more hardware resources.

Data Movement

Efficient operand reuse and local communication are important because memory movement can become a bottleneck.

Control Complexity

Hundreds of processing elements must remain coordinated during loading, computation, draining, and output.
