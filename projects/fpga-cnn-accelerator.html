01OVERVIEW

From CNN Computation to FPGA Hardware

This project explores the design of a dedicated hardware accelerator for fundamental CNN inference operations using an FPGA-oriented RTL architecture.

The accelerator decomposes the computation into dedicated 3×3 convolution, ReLU activation, and 2×2 max-pooling blocks and connects them through clocked pipeline registers. The design was verified through simulation and taken through the Xilinx Vivado synthesis flow for hardware analysis.

Scope

The implementation is intentionally a simplified, verified FPGA-oriented CNN accelerator. It demonstrates the hardware architecture and verification concepts without claiming a production-scale CNN engine, full image streaming system, large parallel MAC array, or complete sliding-window engine.

Pipeline Stages

Stage 1 · Convolution

Performs the 3×3 weighted sum that forms the core CNN computation.

Applies the nonlinear activation using sign detection and selection logic.

Stage 3 · Max Pooling

Reduces a 2×2 activation region to its maximum value.

Stage 4 · Registered Output

Captures the processed result at the output boundary.

03CONVOLUTION ENGINE

3×3 Convolution

The convolution block accepts a 3×3 input window and a 3×3 kernel and performs nine multiplication operations followed by accumulation to generate one convolution output.

3 × 3 INPUT WINDOW × 3 × 3 KERNEL
a0 a1 a2w0 w1 w2Σ(ai × wi)
a3 a4 a5w3 w4 w5+ accumulated terms
a6 a7 a8w6 w7 w8→ output

MAC Foundation

The fundamental operation is:

Accumulator ← Accumulator + Input × Weight

The MAC structure provides the arithmetic foundation for convolution and can be extended toward more parallel accelerator architectures.

04ACTIVATION & POOLING

ReLU Activation

ReLU(x) = max(0, x)

Negative values are suppressed to zero, while non-negative values pass through. In hardware, this can be implemented using sign comparison and selection logic.

2×2 Max Pooling

c   d

Comparator-based selection reduces the four inputs to the strongest activation, reducing spatial representation and subsequent computation.

05PIPELINING

Why Pipeline the CNN?

The major architectural focus is inserting registers between the main computational stages instead of treating the CNN datapath as one long combinational path.

CONV→REGISTER→RELU→REGISTER→POOL→REGISTER

Latency vs. Throughput

Latency

The number of clock cycles needed for one input to propagate through the pipeline.

Throughput

The rate at which outputs can be processed after the pipeline has been filled.

Trade-Off

Pipeline registers add stages and storage, but allow multiple operations to be in progress concurrently.

Architecture

The project uses pipelining as a classical computer-architecture technique for improving processing throughput.
