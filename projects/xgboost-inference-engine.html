01OVERVIEW

From XGBoost Model to RTL Hardware

This project implements hardware inference for a trained XGBoost classification model using synthesizable Verilog RTL. Instead of executing the model entirely in software, the decision-tree inference process is mapped onto dedicated digital hardware.

The accelerator accepts a quantized feature vector, traverses the trained ensemble, accumulates class scores, applies bias and fixed-point saturation, and selects the final prediction through an Argmax unit.

The Architecture Story

The project has two architectural stages. A sequential implementation was first developed and functionally verified, establishing an approximately 3,875-cycle per-inference baseline. The architecture was then redesigned to exploit tree-level parallelism and pipelined traversal, making latency the primary optimization target while explicitly exposing the resulting hardware-resource trade-off.

Feature Register File

The complete 144-feature input vector is held locally so that tree evaluators can access the feature selected by each decision node during inference.

Model Memory

The trained XGBoost model is converted into hardware-readable memory initialization files. Node information includes the leaf indicator, feature index, and threshold or leaf value required to reconstruct decision-tree traversal in hardware.

Tree Evaluator

At each decision node, the evaluator compares the selected feature with the stored threshold. The result selects the left or right child, and traversal continues until a leaf is reached.

Final Argmax

The maximum final class score determines the prediction.

Bias + Saturation + Argmax

Class Score = Tree Score + Bias Wide Internal Score → Saturation → Output Score Prediction = argmax(Score0, Score1, Score2)

Saturation prevents signed fixed-point overflow from wrapping around, while Argmax converts the three final class scores into the predicted class.

06FIXED-POINT DESIGN

Q22.14 Representation

The accelerator uses Q22.14 fixed-point representation for model and score arithmetic. Fixed-point computation provides deterministic numerical behavior while avoiding the hardware cost of a floating-point datapath.

Deterministic ArithmeticHardware-Friendly Fixed Integer WidthOverflow Protection

Saturation

Internal accumulation can use a wider representation than the final output. The saturation stage range-checks the result and clips values outside the representable output range instead of allowing wraparound.

08SYNTHESIS & TRADE-OFFS

FPGA Synthesis

The RTL is synthesized using AMD/Xilinx Vivado. Synthesis maps the Verilog architecture into FPGA resources including LUTs, flip-flops, memories, arithmetic resources, and routing.

Why the Optimized Design Costs More

Sequential

Reuses hardware and reduces resource demand, but requires more sequential execution.

Parallel

Replicates tree evaluators to expose large amounts of concurrency.

Pipeline

Adds registers between traversal stages to improve temporal throughput.

Reduction Tree

Uses parallel additions to avoid one long score-accumulation chain.

Optimization Priority

01 · LATENCY→02 · RESOURCE UTILIZATION

The current optimization phase prioritizes reducing inference latency first, then evaluates the additional FPGA resource cost required to achieve it.

10MY CONTRIBUTION

What I Built

Designed and implemented the RTL inference architecture for a trained XGBoost ensemble, including feature storage, model-memory representation, decision-tree traversal, fixed-point score accumulation, saturation, classification, and the parallel/pipelined optimization strategy.

Developed and used a self-checking verification flow to compare hardware outputs against golden reference vectors, then used the verified sequential implementation as the baseline for architecture-level latency optimization.

11TAKEAWAY

Trading Hardware for Latency

774 TREES→ PARALLEL EVALUATION→ PIPELINED TRAVERSAL→ PARALLEL REDUCTION→ LOWER LATENCY

The project demonstrates a core accelerator-design principle: machine-learning inference can be reshaped at the hardware level by changing how computation is spatially and temporally organized. The key trade-off is between replicated FPGA resources and inference latency.
